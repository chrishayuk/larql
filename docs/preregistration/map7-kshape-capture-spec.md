# MAP-7 / K-SHAPE — Capture & Harness Specification

**Status:** 📋 v1.0 DRAFT — becomes FROZEN at the commit that lands it;
amendments only as dated Addendum sections.
**Companion:** [`map7-kshape-prereg.md`](./map7-kshape-prereg.md) — the
science and gates. This document owns the corpus, identity, storage,
and harness contract. **Contains no experiment outputs.**

---

## 1. Purpose and scope

One capture over one frozen corpus serves both programmes:

- **served by the static capture:** MAP-7 pair fitting (`i_20 → i_29`),
  T2 instrument gate, PCA bases, CellRouter cells, K-SHAPE-B spectra
  and regime-1 training pairs, margin tertiles, all geometry.
- **NOT servable by any static capture:** K-SHAPE-A joint sweeps and
  all joint verdict cells (each K changes the trajectory), K-SHAPE-B
  regime-2 sequential training, MAP-7 splice evaluation. These are
  live runs that recompute canonical forwards on demand and stamp
  their outputs with the same identity tuple (§2).

Principle: **store inputs, recompute intermediates.** Compute is cheap
here; bytes are not.

## 2. Identity and immutability

Every persisted row and every derived artifact carries:

```text
(corpus_version, split, prompt_id, position, layer,
 model_digest, vindex_digest)
```

- `corpus_version`: `map7-kshape-corpus-v1`. Any change to prompts,
  strata, seeds, or sampling is a NEW corpus version, never an edit.
- `model_digest`: the HF revision SHA of `google/gemma-3-4b-it` as
  resolved in the local cache at extraction time.
- `vindex_digest`: the container's own verification digest (from
  `larql vindex3 verify` when the vindex3 route is used; otherwise
  SHA-256 over the container manifest), recorded once at bring-up.

A top-level `manifest.json` freezes: corpus_version, prompt-file
SHA-256, generation seeds, strata counts, split assignment (explicit
per-prompt), position-sampling rule, probe-layer set, model_digest,
vindex_digest, capture-harness git SHA. **Every consumer refuses to
run on any digest mismatch** (the `freeze_calibration.py` precedent:
refuse on drift, never warn-and-continue).

Live candidate trajectories cannot be reconstructed from the static
blob alone; this tuple is what makes a regenerated intermediate
comparable to a stored one. A recomputed quantity may be used only
after the §7 recompute-parity check passes against the same
`vindex_digest`.

## 3. Substrate and container bring-up

- Model: `google/gemma-3-4b-it` (locally cached), 34 layers,
  d_model 2560, d_ff 10240, vocab 262208 (as loaded from the container).
- Container: freshly extracted dense f16. Two routes exist; bring-up
  pins ONE and records it in the manifest:
  1. `larql vindex3 plan` → `encode` → `verify` (preferred if the
     hook/patching substrate consumes vindex3 containers), or
  2. the legacy `larql extract-index google/gemma-3-4b-it -o …`
     dense f16 vindex (the substrate MAP-1/2/5 ran on; ~18 min with
     cached weights).
  The choice is a bring-up detail, not a scientific parameter; the
  digest requirement is identical either way.
- Execution substrate for capture and splicing: the `larql-inference`
  hooked forward / patching path (`forward/hooks.rs`,
  `forward/infer_patched.rs`, `forward/layer_interventions.rs`) — the
  surface MAP-1/2b/5 validated. All captured values f32.

## 4. Corpus (frozen at commit of the prompt file)

5,000 prompts, generated by a committed deterministic script with
recorded seeds; the prompt file itself is committed and its SHA-256
enters the manifest.

| Stratum | Count | Construction |
|---|---|---|
| general open-ended | 2,660 | diverse open-ended continuations; no template family (includes 160 backfill, see §4.1) |
| entity-swap | 840 | 10 factual domains × 5 template phrasings (= 50 families) × 20 entities/domain, reduced by the §4.1 holdout interaction |
| templated / low-entropy | 500 | deliberately near-forced continuations (lists, form openers) — included to SPAN the margin axis, never pooled silently |
| code | 500 | code continuation (the CellRouter OOD-fragility stratum) |
| non-English | 500 | non-English prose (second OOD stratum) |

Margin tertiles are computed from measured canonical top-1 margins,
never from these labels (the labels exist to guarantee the margin axis
is populated; the templated-completion confound is handled by
measurement, not by topic).

**Filler/leakage rule:** no prompt may contain the canonical answer of
any entity-swap cell (checked mechanically at generation).

### 4.1 Splits

- 60% train / 20% dev / 20% test, assigned at the PROMPT level and
  recorded explicitly in the manifest.
- Entity-swap: entities are disjoint across splits (per domain,
  12 train / 4 dev / 4 test), AND one template phrasing per domain
  (10 of the 50 families) appears ONLY in test (held-out templates).
  **Holdout interaction, resolved with entity disjointness taking
  priority:** a test-only family keeps only its domain's 4 test
  entities; its train/dev-entity cells are dropped, not reassigned
  (10 × 16 = 160 dropped cells → stratum count 840). The 160 slots
  backfill into the general stratum so the corpus stays 5,000.
- Hyperparameter selection touches dev only; test is evaluated once
  per dev-selected configuration (prereg §4.2, §5.4).

### 4.2 Position sampling

Per prompt: the final `min(32, len − 8)` positions (positions with
index < 8 are never sampled). Deterministic; assigned after the
prompt-level split; recorded in the manifest. Ceiling: 160,000
position records.

## 5. Persisted record (per sampled position)

| Field | Shape / type | Size |
|---|---|---|
| boundary residuals `i_L`, L = 0..34 (prereg §3.2 convention) | 35 × 2560 f32 | 350 KB |
| FFN-input residuals at probe layers (§6.3) | 6 × 2560 f32 | 60 KB |
| top-256 logits (ids u32 + values f32, canonical forward) | 256 × 8 B | 2 KB |
| native top-1 margin, NLL of realized token, entropy | f32 scalars | — |
| identity + stratum/template/entity metadata | JSONL | — |

≈ 412 KB/position → **≈ 66 GB** at the 160k ceiling.

Full-vocab logits are persisted only for a deterministic 5% audit
subsample (≈ 8.4 GB). Verdict KL is computed live in paired runs
(canonical and arm in the same process); the top-256 record serves
rank/containment metrics and truncated-KL screens only, and any
truncated-KL number is labelled as such.

**Format:** safetensors shards, one per (split, stratum, 128-prompt
chunk) — 128 keeps the per-shard write buffer ~1.5 GB — tensor keys `b{L}`, `ffn_in{L}`, `logits_top_i`,
`logits_top_v`, row-aligned with a JSONL metadata sidecar; plus
`manifest.json`. All f32 little-endian (bf16/f16 storage is
prohibited for fitted/scored quantities — the bf16-substrate hazard).

### 5.1 Storage budget

| Item | Size |
|---|---|
| position records | ~66 GB |
| full-logit audit subsample (5%) | ~8.4 GB |
| manifest, prompts, metadata | < 0.1 GB |
| **total static capture** | **~75 GB** |

The harness **refuses to start bulk capture with < 120 GB free** on
the target volume.

## 6. What is captured where

### 6.1 Boundary residuals — all layers

`i_L` for every L ∈ 0..34 (prereg §3.2: `i_L` = residual entering
layer L; `i_0` = embedding output, `i_34` = final pre-norm). Capturing
all boundaries removes any probe-choice risk for MAP-7 and the
boundary-convention debug variants.

### 6.2 FFN-input residuals — probe layers only

The value passed to the production per-layer FFN dispatch — i.e. the
raw post-attention residual row at exactly the site a `FfnBackend`
substitution observes, with the pre-FFN norm applied INSIDE the
dispatch as in production (the MAP-2b lesson: never hand-roll the
norm outside `run_ffn`).

### 6.3 Probe layers (frozen)

`{3, 9, 17, 21, 26, 31}` — spanning early / mid / T3 interior
(21, 26) / late band (31). K-SHAPE-B diagnosis and regime-1 training
run at these layers; K-SHAPE-A joint sweeps involve all layers and are
live runs regardless.

## 7. Not persisted — the recompute contract

Gate projections, up projections, gated activations `a_i`, tail
objects `E_K`/`a_tail`, and K/V are **never persisted**. They are
recomputed on demand from (vindex_digest, layer, stored FFN-input
residual).

**Recompute parity:** at capture time, for a deterministic 0.1%
subsample of (position, probe-layer) cells, the harness stores SHA-256
checksums of the f32 byte serialization of the post-GEGLU FFN
activation vector `k(x) = φ(g·x)·(u·x)` — one object validating the
gate projection, up projection, and pre-FFN norm jointly. Any analysis process recomputing intermediates must first
reproduce these checksums **exactly** for the same `vindex_digest`;
mismatch is a hard refusal. (Checksums, not values — respecting
"do not persist intermediates" while keeping bit-parity checkable.)

## 8. Harness contract

Proposed home: `crates/larql-inference/examples/map7_kshape_capture.rs`
(name reserved here; no code in this commit). Requirements:

- **Refusals (hard, non-overridable):** prompt-file digest mismatch;
  container digest mismatch; free-disk < 120 GB; any self-test failure.
- **Determinism:** capture is single-threaded per prompt or otherwise
  ordered such that two runs over the same 8-prompt smoke set produce
  bit-identical shards.
- **Self-tests, run before bulk capture, results printed and stored:**
  1. smoke determinism (above);
  2. recompute parity on the smoke set (§7 checksums round-trip);
  3. splice floor pre-check: true captured `i_29` re-injected through
     the patching path reproduces the unmodified forward bit-identically
     on the smoke set (prereg §4.5's floor, exercised early);
  4. boundary sanity: `i_0` equals the embedding output and `i_34`
     feeds the final norm to reproduce the canonical logits
     bit-identically.
- Output is append-only; a completed shard is never rewritten. Partial
  captures resume by shard, never by overwrite.

## 9. Bring-up sequence (ordering is part of the freeze)

1. Extract + verify the container; record digests; pin the container
   route (§3) in the manifest.
2. Generate + commit the corpus (prompt file, seeds, split manifest).
3. Implement the capture harness; pass all §8 self-tests on the smoke
   set.
4. Bulk capture (~75 GB).
5. **MAP-7 T2 instrument gate** (prereg §4.1). Record the result in
   the registry.
6. Only then: MAP-7 T3 arms and K-SHAPE verdict cells, independently.

No verdict-bearing number exists before step 5 passes.
