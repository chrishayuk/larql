# PR #669 design review: `1ba1739a:docs/mem-002-cold-state-design.md`

Reviewer: independent, read-only. Sources were read only through git objects (`1ba1739a`, `aae20ae3`, `e2e0392f`). The only system queries were `which`, `mdutil -s`, `ls`, `sysctl` and `df`. Nothing was built, run, evicted or edited.

Line numbers below are `residency_curve.rs` at `1ba1739a` unless another file is named. "Note §n" refers to the design note, and [R §n] to `docs/mem-001-reconnaissance.md`.

## Findings

| 1a | Pre-prefill witness just before the prompt timer | **True.** The pre-prompt reading is `let mut before_res = session.mapped_residency();` at :229. Between it and `let started = Instant::now();` at :281 there is only `process_resources()`, the closure definition and two ledger resets (:279-280), so the gap is microseconds and the reading is outside the timer. It is not printed. The note's derivation "post-prompt minus delta" is exact only when residency did not fall during the prompt, because `resident_delta` uses `saturating_sub` (:255). If residency falls, the derived figure is the post-prompt value, which is **lower** than the true pre-prompt value and could pass a threshold wrongly. In practice this matters only for passes after pass 1, which are never cold. | ADEQUATE (with caveat) | NON-BLOCKING |
| 1b | Cold binding and cold prefill as separate units | For pass 1 the two readings sit next to each other. The binding read (:187) and the pre-prompt read (:229) are separated only by the KV build and `DecodeSession::over_prepared` (:212-213). From pass 2 on, pages from pass 1 are resident. So on main, **cold prefill is in effect only pass 1 of a fresh process, and its witness is about the same as the binding witness.** The note does not say that a cold arm means pass 1 of a fresh process with `--warmup 0`. It also does not say that the instrument's own `"cold"` label (:214-220) is assigned by procedure (`pass == 1`), which makes it "cold by procedure" in the note's own taxonomy (§1). Also, "every bound region" should read "every **mapped** bound region": `mapped_residency` counts only regions with `mapped_bytes > 0` (`prepared/residency.rs:417-425`). Owned or widened operands are read during load and are not in the witness. | AMBIGUOUS | NON-BLOCKING |

It runs after `elapsed` is taken (:311-319), so it is outside the timer. The "pre-step" value for token k is the post-step value of token k−1. | ADEQUATE | — |

| 2a | None→0 failure and the positive control | The failure mode is stated correctly: `Mapped { region, .. } => region.resident_bytes().unwrap_or(0)` (`weights/loaded.rs:37`), and `None` is returned on an `rc != 0` mincore (`physical.rs:297-298`). The proposed control is weaker than it is presented: (i) the deltas are mapping-wide sums, so non-zero deltas show the instrument works on **some** regions, not on "the same regions", and a per-region failure is not excluded; (ii) it shows mincore seeing pages **faulted into this process**, while the binding gate needs mincore to see pages **cached but not mapped by this process**. The record already has the control that tests this: V3's second run read 10.485 GB resident at binding in a fresh process [R §2.2]. The note does not cite it. A protocol should also require the cross-check `ru_majflt × 16 KiB ≈ resident delta` on fault-path arms [R §1.1] and a warm-at-binding control once per method. | AMBIGUOUS | NON-BLOCKING |
| 2b | Boundary-page double count | Correct: whole pages are counted per region, clipped only to the region's length (`physical.rs:283-301`). "Doesn't matter at ~0" is right. | ADEQUATE | — |

The gap from binding witness to prompt is the session build only. **One gap remains:** under F, a concurrent reader (Spotlight importing the new clone) can warm pages **after** a passing binding witness and **during** the timed prompt. The witness cannot see this. Exclusion is listed as a question (§8 Q7), but nothing requires the exclusion to be verified before the first arm. | AMBIGUOUS | NON-BLOCKING |
| 2d | Gate value seen before the outcome | On main, the pre-prompt figure can be computed only from the line printed **after** the prompt, the same line that carries its milliseconds (:262-273). A cold-prefill gate computed that way is not evaluated before the latency is seen, which is the first §5 rule. The binding line (:195-199) is printed before execution. The protocol should gate on the binding line for pass 1, or record the gate decision before the arm runs. | INADEQUATE (as stated) | NON-BLOCKING (bounded fix) |
| 3 | Manufacturing vs classifying, and anti-selection rules | The distinction is clear and correct (§5). ## Recommendation

**ACCEPT WITH BOUNDED CHANGES.** I found nothing blocking. The note's central claims about the code are correct:

- the pre-prompt and per-step reads are mapping-wide and outside the timer;
- cold decode cannot be witnessed before execution on main;
- the None→0 failure mode is stated correctly;
- it stays design-only.

The bounded changes, all text:

1. **Cold arm = pass 1 of a fresh process (fresh clone for F), `--warmup 0`.** Gate on the binding line, which is printed before execution. Do not gate on the derived pre-prompt figure, which appears only after the prompt and is a lower bound under `saturating_sub`. Note that the instrument's `"cold"` label is assigned by procedure. Change "every bound region" to "every mapped bound region".
2. **Strengthen the positive control.** Cite V3's second run (10.485 GB at binding in a fresh process) as evidence that mincore sees cached-but-unmapped pages. Require a warm-at-binding control once per method, and the `major faults × 16 KiB ≈ resident delta` cross-check. Say that the aggregate control does not exclude a per-region failure.
3. **F.**
   - Connect the unobservable shared-extent residual to round 3's unexplained 8.2 µs/fault [R §2.4 (ii)].
   - Separate the `.s7` hash from F arms. As written, the hash re-reads every shared extent immediately before the cold method.
   - Add a per-arm check that `cp -c` cloned rather than copied (`df` delta).
   - Require Spotlight exclusion to be verified before the first arm.
   - Optionally, hash each clone's small `index.json`/`system_graph.json`.
4. **D.**
   - Restate the `mds_stores` cause as the notes' attribution. Plain reads are not expected to trigger indexing; F's file creation is.
   - Require D's displacers to exclude any file that shares extents with `.s7` (the branch list includes `.s6`).
5. **§5 rules.** Add: the threshold and witness quantity are frozen with the gate; the gate decision is recorded before the timed region; F and D arm order is interleaved or counterbalanced; rejected attempts are, or are not, executed and timed, decided in advance; settling and quiet-gate parameters are fixed before the arms or tuned on a separate calibration set.
6. **Claim form 1** becomes "cold unit, observed side effects settled". **§7's failure outcome** must have an operational criterion (admission rate, settle time) set at freeze.
7. **Name the unit** in §3 and §4. State that the §4 signal (the historical "cold token") is not cold decode.
8. **Retrospective vs prospective (9a).** State that a fault- and delta-based latency relationship is retrospective, so it is feasibility evidence and not H1 evidence. State that a prospective model needs the pre-step residency of the selected pages (the missing cold-decode witness) and routing available at decision time. Flag for the scoping/H1 freeze the ambiguity in option 4's "measured fault costs", and that H1's "frozen routing trace" is oracle routing.
9. **Minor citations:** label 59 % as witnessed and 67 % as derived; give the precise source for "post-boot" and for C's "memory pressure".
